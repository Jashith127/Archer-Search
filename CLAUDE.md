# Archer

Personal AI search engine served on `http://archer.localhost:4747`, used as the default search engine in Helium (a Chromium browser) or any browser on Windows, with a companion app for setup and settings. Design and build order are in `concept-note.md`. Keep that note current when a design decision changes.

## Layout
- `src/archer/app.py`: FastAPI routes (`/search` renders the results page, `/suggest`, the lazy `/api/strip/{images|news|videos}`, `/api/similar` (side-panel similar images), `/api/portraits` (Wikipedia thumbnails for AI key facts), `/api/works` (books, albums), `/api/filmography` and `/api/cast` (actor poster grid, film/TV cast), `/api/weather`, `/api/news/thumb` (a news card's og:image when the engine sent no picture, read through `fetcher.lead_image`), `/app` (companion app), `/app/welcome` (first-run setup), `/health`; `/settings` redirects to `/app` and `/setup` to `/app#browser`) and template filters
- `src/archer/views.py`: builds the page view model (SearXNG results plus one hero per query type, discussions, lazy-module flags)
- Ambiguous names: `query.py` turns a trailing kind word ("archer show", "dune movie", "apple company") into `entity_hint`; `views._settle_meaning` then lets the web results choose the meaning (a brand's own site at #1 → its company via Wikidata's official-website property, `wiki.title_for_site`; else the top-ranked matching Wikipedia article) and lists the rest as "Other meanings" chips. A chip links `/search?q=…&about=<exact title>`, which pins the panel
- History and personalization: `history.py` (SQLite store in `data/history.sqlite3`: searches, opened results, site raise/lower/block, remembered meanings, cached vectors), `embed.py` (local embeddings: Model2Vec potion models downloaded to `data/models/`, Ollama `/api/embed`, or hashed lexical vectors as the always-available fallback), `personalize.py` (matching = 0.7·embedding + 0.3·word similarity via concatenated vectors, per-model cutoff, session context, utility/fragment/short-query/spelling/prefix/initials/site-name/product-name rules from `docs/history-evaluation.md`, switchable through `RULES`; "Not related" corrections in the `unrelated` table; reranking `0.6·rank + 0.25·semantic + 0.15·site affinity` plus site preferences, "You found these before" recall, related past searches, history search by meaning, topic clusters), `history_routes.py` (`/api/history/*`: click recording needs only same-origin; reading and changes are CSRF-guarded), `templates/history.html` (`/history`; a search lists matches closest first, each with how it matched from `Personalizer.match_history`), `history_recall.html`. Matches are drawn with `macros.closeness` (five pixel-mark cells in `--mark` violet, from `personalize.closeness`) and the matching model with `macros.model_pill`. `/search` records page-1 searches (not prefetches) and personalizes; `/suggest` puts past searches first. `tests/history_browser_server.py` serves seeded history at :4752 for `tests/history.browser.cjs`. `scripts/export_history.py` exports searches from a Chromium history; `scripts/eval_embeddings.py` evaluates matching on it (variants, new topics, near-misses, replay, optional labels). Change matching rules only with a re-run
- `src/archer/query.py`: query typing (utility, weather, time and define patterns; entity candidate)
- `src/archer/utilities.py`: local instant answers (calculator, units, colour, timestamp, random, currency parsing)
- `src/archer/imagerank.py`: image relevance re-ranking (title/URL term overlap, model numbers weighted, dedupe, drops tiny images and svg icons) and the "similar images" query; used by the Images tab, the strip and `/api/similar`
- `src/archer/visuals.py`: decides before any model call whether an AI answer needs pictures (required / helpful / none) and the image query; `ai_service.visual_verdict` applies the model's keep/hide choice
- AI answer blocks: `Block` in `ai_service.py` (summary, facts, specs, callout, verdict, proscons, products, bars, timeline, quote, table, list, steps, inference, limitation), validated in `validate_block` and drawn by `renderBlock` in `archer.js`. A new kind needs all three plus a line in `ANSWER_PROMPT`
- `src/archer/searxng.py`: the search front (`Search`, alias `SearXNG`): 10-minute cache, dispatch to the configured provider, a fallback chain through every set-up provider (`fallback_order`, `SearchResponse.notice`), rate-limit tracking with a 10-minute skip (`note_limit`, `cooling`, `active_limits`; drawn by `templates/ratelimit_banner.html` with brand colours from `app.ENGINE_COLORS`), and suggestions from the configured source. The SearXNG JSON client lives here too
- `src/archer/searxng_local.py`: SearXNG on Windows without Docker. `install` downloads a pinned upstream release (`PIN`, checksummed tarball), unpacks it under `%LOCALAPPDATA%\Archer\searxng` (a short root, since curl_cffi's DLLs fail to load from long paths) and builds its own Python 3.12 venv with uv, compiled to bytecode along with the managed Python's standard library (a start without bytecode takes ~24 s); `searxng_shim/` (a `pwd` stand-in and a `sitecustomize`) is copied into that venv, because upstream doesn't support Windows. `start` runs it inside a Windows Job Object that kills the whole tree (launcher, Granian and its workers), so a stop, or Archer crashing, never leaves a worker on the port; output stays in memory only, since engine warnings can carry query URLs. Bump `PIN` only after the same check on Windows 11.
- `src/archer/websearch.py`: the other search backends (DuckDuckGo HTML + its image/news/video JSON, Brave API, Google via Serper or a legacy Programmable Search key), keyless Google/DuckDuckGo suggestions, provider labels and 'view on' links. DuckDuckGo has no official results API; Google's Custom Search API takes no new customers and ends 1 Jan 2027
- `src/archer/ai_provider.py`: `PROVIDERS` (DeepSeek recommended, OpenAI, Claude, Ollama, OpenRouter, custom), `resolve`/`readiness`, and one `Provider` speaking three protocols (OpenAI chat completions, Anthropic Messages, Ollama's native `/api/chat` for its context window); `plan` always returns OpenAI-shaped `tool_calls`
- Links in an AI question: `ai_service.question_urls` finds them and `execute` reads up to two through the `read_url` tool before planning (no model call); `sources/github.py` serves github.com/owner/repo from the API (facts plus README) because the HTML page has no readable text. The planner can also call `read_url` (3 per answer)
- `src/archer/sources/`: `wiki.py` (Wikipedia + Wikidata entity panels by kind and person subtype, spelling suggestions, filmography via SPARQL, Retry-After backoff), `weather.py` (Open-Meteo weather, sun, geocoding), `dictionary.py` (Wiktionary), `crypto.py` (CoinGecko), `translate.py` (MyMemory), `places.py` (Photon geocoding, Overpass with a Photon fallback; loaded lazily via `/api/places`), `aimodels.py` (AI model panels from Epoch AI's benchmark zip, cached in `data/` and refreshed daily; matched locally before the Wikipedia entity lookup), `modelprices.py` (API prices from OpenRouter's public model list, cached in `data/` daily; the AI model charts plot score against price when at least three of a chart's models have one; the card's API price tile shows the input and output rates), `credits.py` (film/TV cast and crew and actor filmographies: Wikidata names and roles with Wikipedia photos and posters via `wiki.thumbs`, or TMDB credits when `TMDB_API_KEY` is set and Wikidata has the TMDB id; rendered by `templates/screen_cast.html` and `screen_filmography.html`; `tests/screen_browser_server.py` serves both on fixtures at :4751), `watch.py` (where to watch: TMDB provider logos when keyed, else Wikidata's service IDs drawn with their Simple Icons mark or brand-colour initial), `games.py` (video game panels: Steam price in the home currency, reviews, players, screenshots and PC requirements, CheapShark's PC deals; served by `/api/game`, drawn by `templates/heroes/game.html`, which `search.html` picks for an entity of kind `game`), `fx.py` (USD exchange rate for the home currency: ECB via Frankfurter, CoinGecko fallback, cached 6 h; the AI model card shows its prices in rupees)
- Products: `sources/products.py` builds the panel from search snippets (store product pages only, prices with their size or capacity, review scores, credited photos via `/api/product/photos`), merged with Wikidata's `product` kind; `views._product_hero` decides, `templates/heroes/product.html` draws it, `/api/product` adds a price and a review search. AI Mode emits it as a `product` card (`AIService.product_card`), and answers can use the `specs` block
- Motorsport panels: `wiki.KINDS` adds `car` (car model, before `product`, which typed them too), `race` (also a "Formula One event"), `circuit` (motorsport racing track or street circuit, before `place`) and `f1team` (also any "… in Formula One" article, which Wikidata types only as a multi-topic article); `_kind` reads an F1 driver's occupation (Q10841764) before any P31, because a driver is typed "human", and falls back to the sport (P641) for a race. `wiki._disciplines` folds Wikidata's overlapping sport names into one tag per branch of motorsport. `sources/f1.py` is Jolpica (the keyless Ergast), matched by the Wikipedia url every row carries (current standings first, then the full driver/constructor lists, fetched only for someone not racing now and kept a week): `lookup` (standing with a ladder of the drivers around, every result this season, form stats, career totals — starts/wins/podiums/poles via `total` counts — and titles from the `DRIVER_CHAMPIONS`/`CONSTRUCTOR_CHAMPIONS` tables, a later season asked for once), `next_race` (computed from the season calendar, with the season strip), `grand_prix`, `circuit`, `qualifying`. `TEAM_COLORS` sets each panel's `--team` accent. Circuit outlines are bundled in `sources/circuits.json` (built by `scripts/build_circuits.py` from bacinger/f1-circuits, MIT; drawn in the racing direction from the start/finish line) and matched by position (`circuit_map`); other circuits fall back to OpenStreetMap raceways (`track`, `/api/f1/track`). Routes: `/api/f1`, `/api/f1/next`, `/api/f1/qualifying`, `/api/f1/gp`, `/api/f1/circuit`; each answers `{}` when Jolpica can't be reached and the panel keeps its Wikidata half. Templates `heroes/f1.html` (driver and team), `race.html`, `circuit.html`, `car.html`; the `F1` section of `archer.js` draws everything into server-rendered skeletons: `trackMap` (the circuit as a canvas dot matrix on the brand's pitch, a team-coloured car lapping it at a stepped ~15fps, chequered S/F, distance on hover), `driverForm`/`teamForm` (SVG dot charts per round), the ladder, career strip and weekend card; the qualifying grid is drawn only on a click and only for its own weekend. `tests/motorsport_browser_server.py` serves every panel at :4753 on recorded Jolpica replies (`tests/fixtures/jolpica`). Car pictures are matted rather than cropped (`.ms-` block in `archer.css`), F1/circuit styles are the `.f1-`/`.trk-` block
- Team sports and esports: `wiki.KINDS` adds `club` (football, basketball, American football, baseball, ice hockey teams; before `org`), `league` (also any item in `sports.LEAGUES`), `esteam` (esports team, before `club`) and `esplayer` (occupation "professional gamer", read before any P31 like an F1 driver). `sources/sports.py` is ESPN's public site API (keyless; it refuses a User-Agent containing a URL, so it sends its own `HEADERS`): `LEAGUES` maps Wikidata league QIDs to ESPN slugs, `match` finds a club in a league's team list by folded name, `team` (table, ladder, zones, results, fixtures, live game, record, squad by line, coach) and `league` (tables and this round). `sources/esports.py`: `games_in` reads the game from the article (Valorant first), `valorant` reads VLR.gg's team/player/stats pages (no API: chunked regexes, never one pattern across the page, which backtracks), `liquipedia` reads the game wiki's infobox (one request per 2 s) and the active roster via one `parse` (at most every 30 s; skipped, not queued). VCT seasons: `query.vct` turns "vct 2026", "valorant champions 2024", "vct 2025 emea stage 2" into the local hero kind `vct` (year, event, region); `esports.vct_season` reads VLR.gg's `/vct-YYYY` and `/gc-YYYY` hubs (main Game Changers events only, `_GC_SKIP`) and `_pick` chooses the event to open (named, then live, then a past season's Champions, then the latest finished); `vct_event` parses an event page (champion, grand final, standings with prizes, results, upcoming). VLR.gg's images live on owcdn.net, which answers 403 to a browser that sends no Referer (the results page sends none), so `esports._src` hands them out as `/api/vlr/img/<hex name>` and `esports.image` fetches and keeps them (hex names only); `isHttp` in `archer.js` accepts that path, and VLR logos sit on a light `--plate` because they are drawn for VLR's light pages. A Champions event shows `static/vct-champions-trophy.png` (Riot's studio photograph, background removed); other events and a failed load get the drawn trophy. Routes `/api/sport/club`, `/api/sport/league`, `/api/esports`, `/api/vct/season`, `/api/vct/event`, `/api/vlr/img/{name}`; template `heroes/vct.html`. Templates `heroes/club.html`, `league.html`, `valorant.html` (picked in `search_hero.html` when `esports.game == "valorant"`), `esports.html`, sharing `sport_macros.html`; JS "clubs and leagues", "Valorant" and "esports in other games" sections; CSS `.sp-`, `.val-`, `.es-` blocks. `tests/sports_browser_server.py` serves every panel at :4755 on recorded replies (`tests/fixtures/espn`, `vlr`, `liquipedia`); `tests/test_sports.py`
- Card system: `facts.py` (`shape`, the `fact` filter) turns a panel fact's label into its form (date with years ago, span rail, number + unit, monogram people, place, chips, text); `macros.fact_tile` draws it, and `spec_cell` reuses the date/span/measure forms. Shared pieces in `macros.html`: `day_rail`/`day_ticks` (24 hour cells; `hour_in` and `hours` filters in `app.py`), `range_bar`; CSS `.readout` (label/value sheet), `.splitbar`, `--px-run`/`--px-dot` in the "card system" block at the end of `archer.css`. A new fact label goes in one of `facts.py`'s sets. `tests/heroes_browser_server.py` serves every hero on `test_heroes` fixtures at :4754 (`/gallery`)
- Adding a query type: a pattern in `query.py` (or a utility in `utilities.py`), a builder in `views.py` (`LOCAL_KINDS` or `ASYNC_HEROES`), a `templates/heroes/<kind>.html`, styles in `archer.css`, and a mocked test in `tests/test_heroes.py`
- `src/archer/templates/`: Jinja templates; `heroes/<kind>.html` holds one hero per query type. `/search` streams in up to three parts: `search.html` (header plus a CSS-only `.serp-wait` placeholder, sent before the search runs), `search_main.html` (everything that needs the results; its `<main>` hides the placeholder), and, when the results are ready before a Wikipedia panel (`views.build(defer=True)`, `HERO_GRACE`), `search_late.html`: the panel group from `search_hero.html` (panel, its notices, AI card, cast, filmography) plus works and strips, each `[data-late]` block moved into its `[data-late-slot]` at the top of `archer.js`. So nothing in `search.html` may depend on the search, nothing in the panel group may assume it renders before the results, and a provider redirect after streaming starts becomes a link
- Speed: `tls.py` shares one TLS context across every httpx client (each new one costs ~0.4 s); the launcher binds the port and opens the window before importing the app, on `static/splash.html` (a file:// page that hands over to the companion URL in its #fragment once the server answers); `Search(probe_local=True)` skips a local SearXNG that isn't listening (Windows takes ~2 s to refuse a closed port)
- `src/archer/static/`: `archer.css` (dark theme tokens at the top) and `archer.js` (lazy modules, converters, clock; DOM-only, no innerHTML)
- `src/archer/__main__.py`: launcher. Runs uvicorn in a thread plus a pystray tray icon; if Archer is already running, it only opens the companion app (setup on first run). `--startup` (from the Run key) honours the sign-in delay, SearXNG and `startup_open`. It runs windowless as `.venv\Scripts\archerw.exe`. Native SearXNG is Archer's own process: it starts and stops with Archer, and the tray can start or stop it. When it manages SearXNG's Docker container instead, the tray has Start/Stop Docker, and Docker Desktop starts hidden (`companion.quiet_docker_desktop`, which also takes over Docker's own sign-in entry while Archer starts with Windows). `archer/__init__.py` pins OpenBLAS to one thread (otherwise it commits ~350 MB); keep that before any numpy import
- `src/archer/config.py`: settings, loaded from `ARCHER_*` env vars and `.env`
- `src/archer/autostart.py`: the "Start with Windows" toggle (HKCU Run key, with `--startup`; `refresh` rewrites older entries)
- `src/archer/companion.py`: first-run state (`data/companion.json`), installed-browser detection and opening a browser's search-engine settings, `search_setup` (reads a Chromium profile to tell whether Archer is the default with suggestions; Helium's dialog has a suggestions field (`SUGGEST_FIELD`); in stock Chromium only the engine discovered from `/opensearch.xml` has one), and where SearXNG runs (`settings.searxng_runtime`: `searxng_local.py` natively, a Docker container, or an external instance; unset, it is native when a native install exists, `config.native_searxng_installed`)
- Companion app: `settings_service.py` (field schema with provider cards and `when` conditions, validate-then-write `.env`, live apply, masked secrets, connection tests), `settings_routes.py` (`/api/settings*`, `/api/app/*`, guarded like AI POSTs), `envfile.py` (comment-preserving `.env` edits), `window.py` (opens a page as a Chromium `--app` window), `templates/companion_base.html`, `companion.html` (panes), `welcome.html` (setup wizard), `companion_fields.html` (shared field macros), `static/companion.css`, `static/companion.js`. A new setting needs a field in `config.py` and a `Spec` in `settings_service.py`; place it in a pane or setup step by name. `tests/companion_browser_server.py` serves it on a throwaway config at :4790
- AI UI: `templates/ai_panel.html` (one panel; Balanced card or AI Mode via `body.ai-fullview`, turns cloned from a `<template>`), AI section of `archer.js` and `archer.css`
- `scripts/install.ps1`, `install.cmd`: one-click install (uv sync, shortcuts, launch)
- `installer/`: ArcherSetup.exe (`build.ps1`, `build.sh`). `src/Frame.cs` (frameless WebView2 window, Chromium `--app` fallback), `Api.cs` (token-guarded JSON API), `Installer.cs` (unpack, uv, native SearXNG, shortcuts, `.env` choices), `Uninstaller.cs` (`--uninstall`); `ui/` is the page (hero, provider choice, install, done, uninstall). `--dry` simulates every step; `tests/installer.browser.cjs` drives it at :4791

## Commands
- `uv sync`: install
- `uv run pytest`: tests
- `uv run archer --no-tray`: run in the foreground for development

## Rules
- Bind to 127.0.0.1 only, and keep `TrustedHostMiddleware` in place. The public host must stay a `*.localhost` name.
- Never return a full API key to the browser; the companion app shows masked hints only. Tests must use a temporary `.env`, never the real one, and a temporary history database (`tests/conftest.py` points `history.DB_PATH` at `tmp_path` and pins lexical matching).
- History stays on this computer. Never send queries, visits or vectors to a remote service; embeddings run locally (Model2Vec or a local Ollama). With history paused, nothing about a search may be written to disk. The history page uses `site_badge(host, cached=True)` so it never triggers a favicon lookup, and anything that deletes history ends with `History.scrub()`.
- A plain `GET /search` must never trigger a paid AI call. AI generation goes through a POST that checks `Sec-Fetch-Site: same-origin`.
- Keep the `/suggest` response in OpenSearch JSON format: `[query, [completions], ...]`.
- The results page sends a strict CSP (`script-src 'self'`) and `no-referrer`. Keep scripts in `static/archer.js`, not inline.
- Upstream engines and Wikimedia rate-limit quickly. Don't burst-test live queries; prefer the mocked tests in `tests/`.
- In Jinja, avoid dict keys that shadow dict methods (`pop`, `items`, `keys`, `values`, `get`, `update`).
